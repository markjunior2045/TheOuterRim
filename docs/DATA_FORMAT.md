# DATA_FORMAT.md — game data (outer-rim-data/0.1)

The card data the rules core reads (`PLAN.md` T2.2). It encodes the abilities classified in `EFFECTS.md`; it is **not** the transcription (`TRANSCRIPTION_FORMAT.md`), which keeps the printed text and stays the source for localization.

Checked by `tools/validate_data.py` against `data/schema/registry.json`. Tests: `python -m unittest discover -s tools/tests`.

## Layout

```
data/
  schema/registry.json          what card data may use: effects, conditions, timings, events, selectors, card kinds
  map/{pack}-map.json           map graph (MAP_FORMAT.md)
  packs/{pack}/pack.json        pack manifest
  packs/{pack}/cards/*.json     card data, one file per deck or group
  packs/{pack}/loc/en.json      English strings, generated by tools/build_loc.py from data/transcription/
```

## Pack manifest (`outer-rim-pack/0.1`)

| Field | Content |
|---|---|
| `id` | stable pack id: `base`, `expansion` |
| `version` | semantic version; a save records the packs and versions it used (`DECISIONS.md` §7) |
| `depends` | ids of packs this one needs (`expansion` depends on `base`) |
| `map` | the pack's map file, if any |
| `cards` | card data files |
| `localization` | language → strings file |

## Card files

```json
{ "format": "outer-rim-data/0.1", "pack": "base", "file": "market-gear",
  "source": "data/transcription/market/base-market-gear.json", "cards": [ ... ] }
```

Every card has `id`, `kind`, `abilities`, and the fields of its kind in `registry.card_kinds` (no more, no less; nullable fields are written as `null`). The `id` is the image id from the extraction, so card, art and transcription share one stable key.

| Kind | Fields |
|---|---|
| gear | `deck`, `cost`, `traits`, `patrol_icon` |
| mod | as gear, plus optional `slot` (the slot types it may occupy, for Smuggling Compartment-8) |
| crew | as gear, plus `skills`, optional `faction`, `droid` |
| cargo | as gear, plus `destination`, `cannot_buy_on` (space ids), `delivery_check` (`{ success, else_databank }` for ILLEGAL cargo), `reward` (effects) |

| ship_sheet | `market_card` (the market card that buys it, or `null` for the starter sheet), `sides`: each with `image`, `role` (`ship_goal`, `flipped`, `starter`), `cost`, `slots`, `stats` (`hyperdrive`, `ship_combat`, `hull`), `traits`, `abilities` |
| character | `ground_combat`, `health`, `skills`, `setup` (`databank` number and starting `reputation` list; faction `"choice"` for Lando), `sides`: front and back, each with `image` and `abilities` |
| contact | `class` (white, green, yellow, orange), `faction` or `null`, `droid`, `databank` (the card resolved on encounter, R-12.15) |
| patrol | `faction`, `level`, `combat` (`null` for level 4, R-11.6), `reward` (effects) |
| player_board | `color`, `slots`, `fame_track` (`min`, `max`) |
| starting_asset | databank cards #90 to #92: `number`, `variant`, `starting_planet`, `asset_kind` (cargo, job, bounty), `destination`, `reward` (R-3.15) |

A slot is `{ "types": ["job", "bounty"], "count": 2 }`: `types` lists the asset types the slot accepts ("job or bounty"), `count` how many cards of those types fit. `count` is the number of printed boxes with that label: "CREW" printed three times is `{ "types": ["crew"], "count": 3 }`. A box printed "X2" holds two cards (R-14.14) and counts as 2; in the base game only Slave I (the flipped Firespray-31 Patrol Craft) prints one, "MOD X2" (checked against the physical sheet, 2026-11-05). Since placement is free (R-14.17), separate boxes and an "X2" box behave the same. Two-sided cards keep their abilities on each side; their text keys start with the side (`"front.upper.0"`, `"sides.1.text.0"`). Goals are abilities with a `goal` timing whose `progress` is a count of events, a state, an event with a condition, or a step ability (`EFFECTS.md` §3.5).

The validator also checks consistency between sets: contact tokens per class match the contact spaces on the map (R-12.4), and each faction has one patrol token of each level (R-11.3).

Further kinds (job, bounty, ship, encounter, databank, AI) are added to the registry as their decks are encoded.

Player-facing text never appears in card data (`DECISIONS.md` §3). An ability's `text` is a key relative to the card: `"text.0"` resolves to `"<card id>.text.0"` in the pack's localization file. Icons stay as `{PLACEHOLDERS}`.

## Abilities

```json
{ "text": "text.1",
  "timing": { "type": "window", "window": "dice_modify", "scope": ["ground_combat"] },
  "limit": "once_per_combat", "optional": true,
  "condition": { "cond": "has_skill", "skill": ["strength"] },
  "cost": [ { "op": "credits.spend", "amount": 2000 } ],
  "effects": [ { "op": "dice.turn", "from": ["focus"], "to": "crit", "count": 1 } ] }
```

| Field | Meaning (`EFFECTS.md` §2) |
|---|---|
| `timing` | `passive`, `step` (planning / action / encounter), `trigger` and `replacement` (an event from `registry.events`, with an optional filter condition), `window` (dice modification in a test, combat or delivery roll), `goal`, `setup` |
| `limit` | `once_per_turn`, `once_per_combat`, `once_per_test` |
| `optional` | "may" (R-21.2) |
| `condition` | must hold for the ability to be used |
| `cost` | effects paid in full before `effects` ("to", R-21.4) |
| `effects` | a sequence of effect nodes |
| `errata` | rule id (`R-24.x`) when the encoded effect follows an erratum instead of the printed text |

## Effects, conditions and amounts

- **Effect node:** `{ "op": "<id>", ...parameters }`. Ids and parameters are listed in `registry.effects`. Control nodes (`if`, `choice`, `may`, `to`, `unless`, `test`, `combat`, `dice.roll`) nest effect lists, so a card is a small tree.
- **Condition node:** `{ "cond": "<id>", ...parameters }` from `registry.conditions`; `all`, `any` and `not` combine them.
- **Amount:** an integer, or `{ "up_to": { "max": n } }`, `{ "any": {} }`, `{ "all": {} }`, `{ "per": { "each": n, "counter": "..." } }`, `{ "times": { "factor": n, "of": "spent" } }`.
- **Selectors** (`player_sel`, `faction_sel`, `space_sel`, `patrol_sel`, `opponent`, `asset_filter`) are a plain string (`"self"`, `"planet"`) or a one-key object (`{ "choose": { "who": "other" } }`).
- **Custom handlers:** `{ "op": "custom", "handler": "<id>" }` for the exceptions in `EFFECTS.md` §8. The handler list is closed: a new one is a registry change.

## Versioning

Every file carries its format version. Adding an effect, condition or card kind to the registry is a minor change and does not break existing data. Renaming or removing one bumps the version and needs a migration of the card files.
